Stats-portal provider API

Per-provider standing on the vanity-market requestor fleet: current ban status, the enforced performance targets, measured performance, and ready-to-display hints — including how much a provider should lower its price to meet the efficiency target.

GEThttps://stone.vanity.market/nmpdmxzhrm/ban-server/api/v1/portal/providers/<providerId>

providerId is the provider's node id (0x + 40 hex chars, as shown on stats.golem.network). Responses are JSON; unknown providers return 404 {"error":"Provider not found"}. CORS is open (Access-Control-Allow-Origin: *), so the endpoint can be called directly from browser code. No auth. Data refreshes roughly every 30 seconds.

curl -s https://stone.vanity.market/nmpdmxzhrm/ban-server/api/v1/portal/providers/0x6544...9e02

Response fields

FieldMeaning
score, category0–100 reputation score and bucket: trusted / reliable / average / underperformer / new / blacklisted / banned.
statusBan state: banned + activeBan (reason, expiresAt; bans expire automatically), bansLast24h and nextBanHours (ban durations escalate — the Nth ban within 24 h lasts N hours), activeAgreements, lastSeen.
targetsThe thresholds the fleet enforces for this provider: efficiencyTarget (TH/GLM — terahashes delivered per GLM billed) and speedTarget (H/s per agreement). relaxed: true means a per-provider override applies (good performers earn a more lenient target automatically).
performanceMeasured inside the freshest window with billing data (window: d1 → d7 → all): agreements, workHashes, costGlm, rented hours, efficiencyThPerGlm, avgSpeedHps, avgCostPerHourGlm, bans issued in the window.
pricingThe provider's own offered price list (scraped from stats.golem.network; null until fetched): priceCpuHour (GLM/h per busy CPU thread — the coefficient that matters most), priceEnvHour, priceStart, monthlyPriceGlm.
hintsActionable messages to show the provider — see below.

Hints

Each hint is {id, severity, message, data?}. message is display-ready English; data carries the numbers if the portal wants to render its own copy.

idSeverityMeaning
price-too-highwarning / criticalMeasured efficiency is below the enforced target — the provider will keep getting terminated and banned. data has suggestedPriceCutPct and suggestedMaxCostPerHour: the price cut that meets the target at the provider's current speed (efficiency scales inversely with price). This is the main "lower your price" signal.
speed-below-targetwarningAverage per-agreement speed under the target. Usually capacity split across too many concurrent agreements, not pricing — advise fewer parallel agreements or more CPU.
bannedcriticalActive ban, with expiry and reason. Bans lift automatically.
ban-escalationwarningBans in the last 24 h escalate the next ban's duration; a clean 24 h resets it.
headroominfoEfficiency well above target — pricing headroom; sustained ≥2× target earns an automatically relaxed target.
staleinfoNo agreements with this fleet in 24 h; stats may be outdated.
okinfoMeeting all targets, nothing to do.

Units

efficiency = TH/GLM (hashes ÷ GLM ÷ 10¹²) · speed = H/s · price = GLM/h · work = hashes (attempts). The suggested max price is avgCostPerHourGlm × efficiency ÷ efficiencyTarget — at unchanged speed, the price cut needed equals the efficiency shortfall.
